**3. `flatten_config(config)` function:**
- If config has any top-level key that is a section name (inference, nn, training, sampling, backward, output), treat it as nested and flatten.
- If config is already flat (all keys are field names, no section keys), return as-is (backward compatibility).
- Flattening maps new names to old names: `config['training']['learning_rate']` -> flat `{'lr': 0.01}`.
- Also accept old flat names in nested sections for gradual migration: `config['training']['lr']` works too.
- Check for DEAD_FIELDS and raise ValueError listing them with suggested replacements.
- Check for unknown keys (not in any section) and raise ValueError naming the offending key.

**4. `validate_config(config)` function:**
- Accept both flat and nested configs.
- If nested, flatten first.
- Validate required fields are present (num_epochs, loss_fn are required when approximation_method='nn').
- Validate types where possible.
- Return the flat config dict (never mutate input).
- Error messages must name the offending field and its section: "Missing required field 'num_epochs' in section 'training'"

**5. `get_default_config()` function:**
- Returns a flat config dict with all fields set to their defaults.
- Useful as a template.

**6. Helper: `_detect_format(config)` function:**
- Returns 'nested' if any top-level key is a section name.
- Returns 'flat' otherwise.

Implementation notes:
- Do NOT import torch or any heavy dependencies in this module. It's pure Python + typing.
- Build a reverse mapping from old_name -> (section, new_name) for efficient flat-field lookup.
- The module must be importable independently of the rest of NCE for testing.
