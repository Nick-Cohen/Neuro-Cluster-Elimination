# Advisor Update — 2026-06-12

*FYI / progress. The core result is holding up; this week was write-up + hardening.*

**TL;DR.** Our "bucket merging" extension to Neural Bucket Elimination (NeuroBE) continues to
show a large win — roughly **6–7× lower partition-function error (up to ~100× on the hardest
grid), while also running faster** — with a consistent sweet spot when each merged cluster
eliminates 8–16 variables. I started the paper this week and hardened the experiment pipeline
so the results are reproducible at scale.

## Where things stand
The method and headline numbers are stable. Effort has shifted from *getting* results to
*publishing* them: a full paper skeleton exists, and a clean 435-run sweep (29 problems × 5
merge settings × 3 seeds) is running to produce a single consistent results table.

## Progress since last update
- **Paper draft started** (abstract → method → experiments → related work). Thesis: merging
  reduces the *number* of neural message approximations, and since approximation error
  compounds as messages propagate, fewer approximations means much lower final error.
- **Pipeline hardened for big runs:** fixed a memory-blowup class that hit wide / multi-valued
  clusters by sizing GPU work dynamically to free memory; added a backtracking merge that
  removes wasted cluster width. All changes are backward-compatible.
- **Knowledge base** of verified citations + concept notes set up to support writing (it also
  caught a mis-citation: NeuroBE is UAI 2022, not AAAI 2022).

## Results worth seeing
- Headline 4-problem table (grids, pedigree, RBM): no-merge is the *worst* accuracy point on
  every curve; the 8–16 sweet spot captures essentially all the gain before exact cost returns.
  (Figures being regenerated to publication quality.)
- A clean negative result: on high-cardinality pedigrees, merging to 16 variables is provably
  infeasible (exact targets would sum over ~10¹¹ terms) — a real limit, worth stating.

## Risks / open questions
- **Repo hygiene blocker:** several working modules the experiments depend on are not yet

  and gates a clean refactor before release.
- **Canonical run set:** curated vs automated sweeps disagree on a few cells (seeds/sampling);
  I'll pick one consistent source before the table is final.
